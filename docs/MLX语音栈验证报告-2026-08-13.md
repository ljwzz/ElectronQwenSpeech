## 环境与固定依赖

源仓验证机器为 Apple M5 Pro、64 GB 内存、macOS 26.6.1 arm64。两个 MLX
Sidecar 环境均为 Python 3.12.13，并固定：

```text
mlx-audio==0.4.8
mlx==0.32.0
mlx-lm==0.31.3
```

ElectronQwenSpeech 环境路径：

- TTS：`services/tts-sidecar/.venv-mlx`；
- ASR/Forced Aligner：`services/asr-sidecar/.venv-mlx`。

MLX 的设备选择、同步和内存 API 见
<https://ml-explore.github.io/mlx/build/html/python/devices_and_streams.html> 与
<https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.get_peak_memory.html>。

MLX 的公开 Python API 可验证 Metal 可用、默认设备为 `gpu:0` 并执行显式设备
probe，但不提供逐算子 fallback trace。本报告的“无运行时 fallback”指运行时、
模型 loader、环境依赖和默认设备均不存在替代模型后端；tokenizer、音频解码与
NumPy 转换的 CPU 预处理不属于模型后端 fallback。

真实对齐异常返回 `ALIGNMENT_FAILED`。

## 源仓历史性能对照

以下结果仅保留源仓历史基准。四组历史命令分别在目标 venv 的全新 Python 进程
中运行；每个进程加载一次模型并记录首轮与第二轮推理。结果是单次工程基准，
不是统计显著性结论。

TTS 生成存在随机性，两套历史运行时输出的音频时长不同，因此 RTF（推理秒数 /
音频秒数）与实时倍速是主要归一化指标。计时结束前同步后端。

OS 最大 RSS 读取 `resource.getrusage(RUSAGE_SELF).ru_maxrss`，其定义见
<https://docs.python.org/3.12/library/resource.html>。MPS 与 MLX 框架内存 API 的
语义不同，并列值及差异只用于历史工程观察，不表示同口径的物理内存归因。
